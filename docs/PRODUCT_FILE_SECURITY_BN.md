# প্রোডাক্ট ফাইল ও উৎস নিরাপত্তা

## নীতি

NB Engineering Tools-এর উৎস, বিল্ড সিস্টেম ও ভেন্ডর টুলিং এই ওয়েবসাইটের সঙ্গে
কোনোভাবেই যুক্ত নয়। ওয়েবসাইট শুধু **গ্রাহকের জন্য প্রস্তুত ডেলিভারি প্যাকেজ**
বিতরণ করে।

## যা কখনো রিপোজিটরি বা সার্ভারে যাবে না

- `SecurityBuild/`, `DeveloperBackup/`, `VendorTools/`
- Vendor Recovery Manager ও যেকোনো private recovery সিস্টেম
- যেকোনো private key, `.pfx`, `.nbk`, `.nbrk`
- LSP / CS / source / build প্রজেক্ট
- ভেন্ডর ও গ্রাহক লেজার, এবং যেকোনো secret

এই তালিকার কিছু ভুল করে দেখা গেলেও তা কোনো আউটপুট, লগ, কমিট বা ডকুমেন্টে
লেখা হবে না।

## গ্রাহক ডেলিভারি প্যাকেজে যা থাকে

1. সাইন করা চূড়ান্ত ইনস্টলার
2. গ্রাহক গাইড
3. পর্যালোচিত EULA
4. রিলিজ নোট
5. SHA-256 চেকসাম
6. অ্যাক্টিভেশন ও সাপোর্ট নির্দেশনা

## ফাইল কোথায় থাকে

```text
❌ apps/web/public/…            কখনো নয় — পাবলিক, ক্যাশযোগ্য, অননুমোদিত
❌ পাবলিক S3 বাকেট              কখনো নয়
✅ প্রাইভেট ডিস্ক (`private`)   ডিফল্ট: storage/app/private-assets
✅ S3-সামঞ্জস্য প্রাইভেট বাকেট  `NB_PRIVATE_DISK=s3_private`
```

`config/filesystems.php`-এ `private` ডিস্কের `serve` বন্ধ এবং `visibility`
private। Nginx-এর `/storage/` লোকেশন শুধু `storage/app/public` দেখায়, তাই
প্রাইভেট ডিস্কের কোনো ফাইল ওয়েব রুট থেকে পৌঁছানো যায় না।

## ডাউনলোডের নিয়ন্ত্রণ

`App\Services\Downloads\DownloadService` প্রতিটি অনুরোধে যাচাই করে:

| যাচাই | ব্যর্থ হলে |
|---|---|
| রিলিজ প্রকাশিত ও ফাইল আছে | 503 + `missing_file` ইভেন্ট |
| ব্যবহারকারীর entitlement আছে | 403 |
| entitlement প্রত্যাহার করা হয়নি | 403 + `revoked` ইভেন্ট |
| মেয়াদ শেষ হয়নি | 403 + `expired` ইভেন্ট |
| ডাউনলোড সীমা বাকি আছে | 403 + `limit_reached` ইভেন্ট |

সফল হলে `download_count` বাড়ে, একটি `granted` ইভেন্ট লেখা হয় এবং অডিট লগে
রেকর্ড যায়। অবজেক্ট স্টোরেজে স্বল্পমেয়াদি signed URL (ডিফল্ট ১০ মিনিট) দেওয়া
হয়; লোকাল প্রাইভেট ডিস্কে ফাইলটি একই authenticated অনুরোধ দিয়ে stream করা হয়।

ফাইলের পথ **সবসময়** ডেটাবেস থেকে slug দিয়ে আসে — কখনো অনুরোধ থেকে নয়। তাই
path traversal বা arbitrary file read সম্ভব নয়। `DownloadAsset` মডেলে
`storage_path` ও `disk` `$hidden`, তাই কোনো API রেসপন্সে সেগুলো যায় না।

ডাউনলোড রেট লিমিট: প্রতি ব্যবহারকারী/IP প্রতি মিনিটে ১৫টি অনুরোধ।

## চেকসাম

ইনস্টলার আপলোডের সময় সার্ভার নিজেই সংরক্ষিত বাইট থেকে SHA-256 হিসাব করে —
ফর্ম থেকে নেওয়া হয় না। ফলে ঘোষিত চেকসাম আর প্রকৃত ফাইল কখনো আলাদা হতে পারে না।
চেকসাম রিলিজ পাতা, অ্যাকাউন্টের ডাউনলোড পাতা ও অ্যাডমিন — তিন জায়গাতেই দেখানো হয়।

## প্রকাশের আগে

`is_available` সত্য করা যায় না যতক্ষণ `storage_path` খালি — এটি
`DownloadAssetController`-এ বাধ্যতামূলক। অর্থাৎ "উপলব্ধ" অথচ ফাইল নেই — এমন
অবস্থা তৈরি করা অসম্ভব।

ইনস্টলার প্রস্তুত না থাকলে রিলিজ রেকর্ড থাকে কিন্তু "প্রকাশিত নয়" অবস্থায়, এবং
গ্রাহক সৎ বার্তা দেখেন। ডেভেলপার ফোল্ডার থেকে কোনো ফাইল স্বয়ংক্রিয়ভাবে কপি করা
হয় না।

## রিফান্ড ও প্রত্যাহার

রিফান্ড অনুমোদনের সময় `revoke_entitlements` সত্য হলে
`App\Services\Fulfillment\RevocationService` সংশ্লিষ্ট ডাউনলোড entitlement,
এনরোলমেন্ট ও লাইসেন্স প্রত্যাহার করে এবং অডিট রেকর্ড লেখে।
