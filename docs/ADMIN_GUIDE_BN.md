# অ্যাডমিন গাইড

অ্যাডমিন সারফেস: `/dashboard`। এটি সাইটেরই অংশ — কোনো আলাদা প্যানেল বা পেইড
অ্যাডমিন প্যাকেজ নেই।

## রোল

| রোল | কী করতে পারে |
|---|---|
| `super_admin` | সবকিছু; একমাত্র যে রোল বদলাতে পারে (নিজের ছাড়া) |
| `admin` | সব কাজ, রোল বরাদ্দ ছাড়া |
| `editor` | আর্টিকেল ও পেজ লেখা, প্রকাশ, মিডিয়া, রিডাইরেক্ট |
| `instructor` | নিজের কোর্স ও লেসন, এনরোলমেন্ট, আর্টিকেল লেখা |
| `support` | অর্ডার দেখা, অ্যাক্টিভেশন রিভিউ, টিকিট |
| `student` / `customer` | অ্যাডমিনে প্রবেশ নেই |

প্রথম অ্যাডমিন তৈরি:

```bash
php artisan platform:make-admin you@example.com --name="Your Name"
```

কমান্ডটি একবারই পাসওয়ার্ড দেখায়; সঙ্গে সঙ্গে বদলে নিন।

## কনটেন্ট প্রকাশের ধাপ

```text
draft → in_review → scheduled/published → archived
```

- প্রতিটি সংরক্ষণের আগে সার্ভার একটি **রিভিশন** রাখে; যেকোনো সময় ফিরে যাওয়া যায়।
- প্রকাশ করা `posts.publish` অনুমতির অধীন — শুধু সম্পাদনার অনুমতি যথেষ্ট নয়।
- Scheduled করতে হলে তারিখ দিতেই হবে; scheduler প্রতি পাঁচ মিনিটে দেখে।
- প্রকাশের পরে ফ্রন্টএন্ডের সংশ্লিষ্ট ক্যাশ ট্যাগ স্বয়ংক্রিয়ভাবে বাতিল হয়।

### আর্টিকেল প্রকাশের চেকলিস্ট

- [ ] শুরুতেই সরাসরি উত্তর
- [ ] অন্তত একটি মৌলিক উদাহরণ বা হিসাব
- [ ] ইউনিট, অ্যাজাম্পশন ও কোড এডিশন উল্লেখ
- [ ] মৌলিক ডায়াগ্রাম বা স্ক্রিনশট (কপিরাইটযুক্ত টেবিল/চিত্র নয়)
- [ ] নির্ভরযোগ্য উৎস
- [ ] সীমাবদ্ধতা ও দাবিত্যাগ
- [ ] লেখক, রিভিউয়ার ও তারিখ
- [ ] অভ্যন্তরীণ লিংক
- [ ] **ইঞ্জিনিয়ার রিভিউ সম্পন্ন** — AI বা খসড়া লেখা রিভিউ ছাড়া প্রকাশ নয়

সম্পাদকে রিভিউ রেকর্ড না থাকলে সতর্কবার্তা দেখানো হয়।

## আইনি পাতা

ছয়টি আইনি পাতা `requires_legal_review` চিহ্নিত। যতক্ষণ পর্যালোচনা রেকর্ড করা হয়নি,
পাবলিক পাতায় দৃশ্যমান **DRAFT — PROFESSIONAL REVIEW REQUIRED** নোটিশ থাকে।

পর্যালোচনার পরে: ড্যাশবোর্ড → পেজ → সংশ্লিষ্ট পাতা → পর্যালোচকের নাম দিয়ে
রেকর্ড করুন। তখন নোটিশ সরে যায় এবং পর্যালোচকের নাম ও তারিখ দেখানো হয়।

## দাম প্রকাশ

ড্যাশবোর্ড → প্রোডাক্ট → ভ্যারিয়েন্ট → নতুন দাম। দাম **append-only**: নতুন দাম
প্রকাশ করলে আগেরটি নিষ্ক্রিয় হয়, মুছে যায় না — তাই পুরোনো অর্ডারের স্ন্যাপশট
সবসময় একটি বাস্তব দামের দিকেই নির্দেশ করে।

দাম প্রকাশ না করা পর্যন্ত ভ্যারিয়েন্ট বিক্রয়যোগ্য নয় এবং সাইটে "দাম জানতে
যোগাযোগ করুন" দেখানো হয়।

## রিলিজ ও ডাউনলোড

1. ড্যাশবোর্ড → রিলিজ → নতুন রিলিজ (slug, নাম, ভার্সন, রিলিজ নোট)
2. ইনস্টলার আপলোড করুন — সার্ভার নিজেই SHA-256 হিসাব করে
3. code signing ও test অবস্থা হালনাগাদ করুন
4. তখনই "উপলব্ধ" করা যাবে

ফাইল আপলোড না করে "উপলব্ধ" করা যায় না — এটি কোডে বাধ্যতামূলক।

## অর্ডার

- অবস্থা পরিবর্তন state machine-এর মধ্য দিয়ে যায়; অবৈধ পরিবর্তন ৪০৯ দেয়।
- "আবার ফুলফিল করুন" নিরাপদ — grant গুলো idempotent।
- **রিফান্ড দুই ধাপে**: একজন অনুরোধ করেন, তারপর অনুমোদন। অনুমোদনের সময়
  পাসওয়ার্ড-স্তরের সুরক্ষা ও idempotency key ব্যবহার হয়।
- `revoke_entitlements` সত্য হলে ডাউনলোড, কোর্স ও লাইসেন্স প্রত্যাহার হয়।

## অ্যাক্টিভেশন রিভিউ (Phase 1)

```text
submitted → under_review → approved → completed
                ↘ needs_info      ↘ rejected
```

1. গ্রাহক পরিশোধিত অর্ডার ও Machine ID দিয়ে অনুরোধ পাঠান।
2. সাপোর্ট রিভিউ শুরু করেন।
3. **অফলাইন ভেন্ডর প্রক্রিয়ায়** (এই ওয়েবসাইটের বাইরে) কাজটি সম্পন্ন হয়।
4. সাপোর্ট নিরাপদ response লিখে দেন এবং "সম্পন্ন" চিহ্নিত করেন।

> কখনো token, key, বা recovery ফাইলের বিষয়বস্তু গ্রাহকের response-এ লিখবেন না।
> এই সিস্টেমে সেগুলো রাখা হয় না এবং রাখার ব্যবস্থাও নেই।

Machine ID সবসময় masked দেখানো হয় — এমনকি অ্যাডমিনেও।

## রিভিউ মডারেশন

কোর্স রিভিউ শুধু যাচাইকৃত এনরোলমেন্ট থেকেই আসতে পারে এবং `in_review` অবস্থায়
জমা হয়। প্রকাশ করলে কোর্স পাতার ক্যাশ বাতিল হয় এবং rating হালনাগাদ হয়।
প্রকৃত রিভিউ না থাকলে কোথাও কোনো rating দেখানো হয় না।

## সেটিংস

ড্যাশবোর্ড → সেটিংস-এ ব্র্যান্ড টেক্সট ও ফিচার তালিকার মতো সম্পাদনাযোগ্য মান
থাকে (JSON হিসেবে)। দাম, ক্রেডেনশিয়াল, ফোন, ঠিকানা ও আইনি অনুমোদন এখানে **নেই** —
সেগুলো সার্ভারের environment-এ; তালিকা
[CONFIGURATION_CHECKLIST_BN.md](CONFIGURATION_CHECKLIST_BN.md)-এ।

## অডিট লগ

সংবেদনশীল প্রতিটি কাজ (অর্ডার অবস্থা, পেমেন্ট যাচাই, রিফান্ড, ডাউনলোড,
অ্যাক্টিভেশন, রোল পরিবর্তন, প্রকাশ, সেটিংস) অডিট লগে যায়। পাসওয়ার্ড, token,
store credential ও সম্পূর্ণ Machine ID লেখার **আগেই** মুছে ফেলা হয়।
