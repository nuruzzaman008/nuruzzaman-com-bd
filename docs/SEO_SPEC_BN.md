# SEO স্পেসিফিকেশন

লক্ষ্য র‍্যাঙ্কিংয়ের প্রতিশ্রুতি নয়। লক্ষ্য: প্রযুক্তিগতভাবে crawl-যোগ্য, দ্রুত,
নির্ভরযোগ্য এবং মৌলিক কনটেন্ট, যেখানে পাতায় যা দেখা যায় আর structured data-তে যা
বলা হয় — দুটো এক।

## Next.js-এ যা ব্যবহার করা হয়েছে

| ফিচার | কোথায় |
|---|---|
| `metadata` / `generateMetadata` | প্রতিটি রুট |
| `metadataBase` + canonical | `src/app/layout.tsx`, `lib/seo.ts` |
| `app/robots.ts` | রোবট নীতি |
| `app/sitemap.ts` | API থেকে সাইটম্যাপ |
| `app/opengraph-image.tsx` | ব্র্যান্ড টোকেন থেকে তৈরি OG কার্ড |
| সার্ভার-রেন্ডার করা JSON-LD | প্রতিটি প্রাসঙ্গিক পাতা |
| `next/image` | responsive AVIF/WebP, নির্দিষ্ট মাপ |
| `next/font` | self-hosted, কোনো external font request নেই |
| On-demand revalidation | প্রকাশের পরে signed webhook |

## ইনডেক্স নীতি

**ইনডেক্স করা হয়**

- হোম, পরিচিতি, যোগাযোগ
- প্রকাশিত আর্টিকেল ও বিষয় (topic) পাতা
- প্রোডাক্ট ও শপ
- প্রকৃত লেসনসহ কোর্স ও কোর্স তালিকা
- সাপোর্ট, FAQ, রিসোর্স, রিলিজ নোট
- আইনি পাতা

**ইনডেক্স করা হয় না** (`robots.txt` + প্রতিটি পাতার `noindex` — দুই জায়গাতেই)

- কার্ট, চেকআউট, পেমেন্ট ফলাফল
- অ্যাকাউন্ট ও ড্যাশবোর্ড
- সুরক্ষিত লেসন (`/learn/*`)
- সাইন ইন, রেজিস্টার, পাসওয়ার্ড রিসেট
- অভ্যন্তরীণ সার্চ (`/search`)
- খসড়া ও অপ্রকাশিত কনটেন্ট (API সেগুলো ৪০৪ দেয়)

সাইটম্যাপ শুধু প্রকৃত ইনডেক্সযোগ্য URL দেয়। API-ই ঠিক করে কোনটি প্রকাশযোগ্য
(খসড়া আর্টিকেল, লেসনহীন কোর্স, বা অপ্রকাশিত পণ্য কখনো ফিডে আসে না), তাই সাইটম্যাপ
এমন কোনো পাতা দেখাতে পারে না যেটি ৪০৪ দেবে বা noindex বহন করে।

Vitest ও Playwright — দুই জায়গাতেই এটি পরীক্ষা করা হয়।

## Structured data

| পাতা | Schema |
|---|---|
| হোম | `WebSite`, `Organization`, `Person` |
| পরিচিতি / লেখক | `ProfilePage` + `Person` |
| আর্টিকেল | `BlogPosting` (রিভিউয়ার থাকলে `reviewedBy`; অনুমোদিত মন্তব্য থাকলে `comment` + `commentCount`) |
| প্রোডাক্ট | `Product` (+ `Offer`, শুধু প্রকাশিত দাম থাকলে) |
| কোর্স | `Course` (+ `aggregateRating`, শুধু প্রকৃত রিভিউ থাকলে) |
| তালিকা পাতা | `ItemList` |
| সব পাতা | `BreadcrumbList` |

**সততার নিয়ম** — কোডে বাধ্যতামূলক:

- দাম প্রকাশ না করা থাকলে `Product`-এ কোনো `Offer` যোগ করা হয় না।
- প্রকাশিত রিভিউ না থাকলে `Course`-এ `aggregateRating` যোগ করা হয় না।
- `Organization`-এ ইমেইল/ফোন শুধু তখনই, যখন মালিক সেগুলো কনফিগার করেছেন।
- আর্টিকেলে `commentCount` ও `comment` শুধু **অনুমোদিত** মন্তব্য থেকে — পাতায় যত
  দেখা যায়, markup-এও ঠিক তত। একটিও না থাকলে ফিল্ডগুলো একেবারেই থাকে না,
  `0` লেখা হয় না।
- আর্টিকেলে **`aggregateRating` কখনো দেওয়া হয় না**, যদিও পাঠকের দেওয়া তারকা
  পাতায় দেখানো হয়। কারণ Google `Article`/`BlogPosting`-এ review snippet সমর্থন
  করে না; যে rating সার্চ রেজাল্টে সৎভাবে দেখানোই যাবে না, সেটি markup-এ দাবি
  করলে লাভ হয় না — উল্টো structured data-র জরিমানা হতে পারে।

> মন্তব্য SEO-তে সাহায্য করে অন্যভাবে: প্রতিটি অনুমোদিত মন্তব্য পাতায় নতুন,
> মৌলিক লেখা যোগ করে এবং সেটি সার্ভারেই render হয়, তাই ক্রলার তা পড়তে পায়।

Breadcrumb-এর দৃশ্যমান তালিকা ও JSON-LD একই অ্যারে থেকে তৈরি হয়, তাই দুটো
আলাদা হতে পারে না।

## যাচাইয়ের চেকলিস্ট (Rich Results Test)

1. `/` → WebSite, Organization, Person
2. `/about` → ProfilePage + Person
3. `/blog/{slug}` → BlogPosting; headline পাতার `h1`-এর সমান কি না মিলিয়ে দেখুন
4. `/shop/{slug}` → Product; দাম দেখানো হলে Offer আছে, না দেখালে নেই
5. `/courses/{slug}` → Course; রিভিউ না থাকলে rating নেই
5ক. `/blog/{slug}` → মন্তব্য থাকলে `comment`-এর সংখ্যা পাতার তালিকার সমান,
    আর `aggregateRating` নেই
6. `/blog` ও `/courses` → ItemList
7. প্রতিটি পাতায় BreadcrumbList

## পারফরম্যান্স বাজেট

Field 75th percentile লক্ষ্য: LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1।

কোডে যা করা হয়েছে:

- ডিফল্টে Server Component; ক্লায়েন্ট কম্পোনেন্ট শুধু কার্ট, ফর্ম, প্লেয়ার ও
  অ্যাডমিন ইন্টার‌্যাকশনে
- পাবলিক ডেটা ক্যাশড ও tag দিয়ে invalidate হয়
- প্রতিটি পাতায় সমান্তরাল ডেটা fetch (`Promise.all`), waterfall নয়
- তালিকার প্রথম কার্ডের ছবি `priority` — LCP উপাদান lazy নয়
- সব ছবিতে নির্দিষ্ট width/height, তাই CLS নেই
- ফন্ট self-hosted, `display: swap`
- কোনো carousel বা autoplay ভিডিও নেই
- অ্যাডমিন ও কোর্স প্লেয়ারের বান্ডেল আলাদা route group-এ, পাবলিক পাতায় লোড হয় না
- `next/image` AVIF/WebP, একটি quality মান (৭৫) — অপ্টিমাইজার ক্যাশ ছোট রাখে

## রিডাইরেক্ট

পুরোনো URL অ্যাডমিন → রিডাইরেক্ট থেকে ম্যাপ করা যায়। উৎস ও গন্তব্য দুটোই
সাইট-আপেক্ষিক পথ হতে হয়, তাই এটি ওপেন রিডাইরেক্ট হতে পারে না। তালিকাটি
`GET /api/v1/site/redirects` দিয়ে পাওয়া যায় এবং প্রতিটি পরিবর্তনে ফ্রন্টএন্ডের
`redirects` ট্যাগ revalidate হয়।
