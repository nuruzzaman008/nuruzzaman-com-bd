# Phase 2: আলাদা লাইসেন্স সার্ভিস (নকশা)

এই ডকুমেন্টটি **পরিকল্পনা**, বাস্তবায়ন নয়। Phase 1-এ ওয়েবসাইট শুধু অনুরোধ
রেকর্ড করে; কোনো token, key বা ledger এখানে নেই।

## কেন আলাদা

লাইসেন্স ও token ledger হলো অর্থমূল্যবান, append-only রেকর্ড এবং signing key
হলো সবচেয়ে সংবেদনশীল সম্পদ। সেগুলো একটি পাবলিক ওয়েবসাইটের সঙ্গে একই
অ্যাপ্লিকেশন বা একই ডেটাবেসে থাকলে ওয়েবসাইটের যেকোনো দুর্বলতা সরাসরি সেগুলোর
ঝুঁকি হয়ে দাঁড়ায়।

## প্রস্তাবিত রূপ

```text
license.nuruzzaman.com.bd        (আলাদা সার্ভিস, আলাদা ডেটাবেস, আলাদা ডিপ্লয়)
        ^
        |  signed, সীমিত API / webhook
        |
nuruzzaman.com.bd                (এই ওয়েবসাইট)
```

### ডেটা

| টেবিল | ভূমিকা |
|---|---|
| `licenses` | লাইসেন্স ও তার অবস্থা |
| `machines` | machine binding (এনক্রিপ্টেড identifier) |
| `token_ledger` | **append-only** — ইস্যু, ব্যবহার, রিফিল; কখনো update/delete নয় |
| `refill_issues` | কোন রিফিল কবে ইস্যু হয়েছে |
| `usage_events` | সফটওয়্যার থেকে আসা ব্যবহারের রেকর্ড |
| `recovery_snapshots` | রিকভারির সময় নেওয়া অবস্থা |
| `recovery_approvals` | কে, কখন, কেন অনুমোদন করেছে |
| `audit_logs` | সব প্রশাসনিক কাজ |

### নিরাপত্তার শর্ত

- Signing key কখনো Next.js, Laravel API বা মূল MySQL-এ নয় — secrets manager
  বা HSM-সমতুল্য সুরক্ষায়।
- অ্যাডমিনে MFA বাধ্যতামূলক।
- প্রতিটি লেখায় idempotency key, যাতে রিট্রাই দুইবার token ইস্যু না করে।
- সব রিকভারি অনুরোধে দুই-ধাপ অনুমোদন।
- আলাদা ব্যাকআপ ও restore drill।
- রেট লিমিট ও IP allowlist।

### সীমানা

ওয়েবসাইট শুধু এই কাজগুলো করতে পারবে:

| ওয়েবসাইট → লাইসেন্স সার্ভিস | কেন |
|---|---|
| `POST /activation-requests` | অনুরোধ ফরওয়ার্ড করা |
| `GET /licenses/{code}/status` | গ্রাহককে অবস্থা দেখানো |
| webhook গ্রহণ | অনুরোধ সম্পন্ন হলে জানানো |

প্রতিটি কল HMAC দিয়ে সাইন করা এবং শুধু allowlist করা উৎস থেকে গ্রহণযোগ্য।
ওয়েবসাইট কখনো token তৈরি, wallet পড়া বা key ব্যবহার করতে পারবে না।

## Phase 1 থেকে Phase 2-এ যাওয়ার পথ

1. এই ওয়েবসাইটের `activation_requests` টেবিলই ঐতিহাসিক রেকর্ড হিসেবে থাকবে।
2. নতুন সার্ভিস দাঁড় করিয়ে তার নিজস্ব ledger শুরু করা হবে।
3. `ActivationService`-এ একটি ড্রাইভার যোগ করা হবে যা manual workflow-এর বদলে
   সার্ভিসে কল করবে। কন্ট্রোলার ও UI অপরিবর্তিত থাকবে।
4. Manual workflow fallback হিসেবে রেখে দেওয়া হবে।
