# দ্বিভাষিক সাইট (বাংলা + English)

সাইটটি দুই ভাষায় চলে। **বাংলা মূল ভাষা**, তাই বাংলা URL-এ কোনো prefix নেই;
ইংরেজি সংস্করণ `/en/` prefix-এর নিচে।

```
বাংলা    /            /blog            /courses/rcc-footing-design
English  /en          /en/blog         /en/courses/rcc-footing-design
```

ভাষা নির্ধারিত হয় **শুধু URL থেকে** — কুকি, `Accept-Language` বা অবস্থান থেকে নয়।
সার্চ থেকে যে ভাষার লিংকে কেউ আসবেন, ঠিক সেই ভাষার পাতাই পাবেন।

সাইন-ইন করা অংশ (`/account`, `/dashboard`, `/learn`, `/cart`, `/checkout`,
`/login` সহ auth পাতাগুলো) ইচ্ছাকৃতভাবে এই দ্বিভাষিক গাছের বাইরে — সেগুলো index হয়
না, তাই দ্বিতীয় সেট URL রেখে লাভ নেই।

---

## ১. ইন্টারফেসের লেখা

মেনু, বোতাম, লেবেল, খালি-অবস্থার বার্তা — সব
`apps/web/src/lib/i18n/dictionary.ts`-এ, দুই ভাষায় পাশাপাশি।

`Dictionary` টাইপটি **বাংলা এন্ট্রি থেকে** তৈরি, তাই কোনো ইংরেজি স্ট্রিং বাদ পড়লে
**বিল্ড ফেল করে**। ইংরেজি চুপচাপ বাংলায় fallback করতে পারে না — অর্ধেক অনুবাদ করা
ইন্টারফেস একেবারে অনুবাদ না করার চেয়েও খারাপ, কারণ পাঠক বুঝতেই পারেন না কোন অংশটা
তিনি মিস করছেন।

নতুন স্ট্রিং যোগ করার নিয়ম: বাংলা অংশে যোগ করুন, তারপর `npx tsc --noEmit` চালান —
ইংরেজি অংশে কোথায় লাগবে TypeScript নিজেই বলে দেবে।

## ২. যে লেখা অনুবাদ করা হয় না

**আর্টিকেল, কোর্স ও লেসনের শিরোনাম ও বডি** যে ভাষায় লেখা হয়েছে সেই ভাষাতেই থাকে,
দুই সাইটেই। এগুলো `data-authored` দিয়ে চিহ্নিত, যাতে ইংরেজি-পাতার স্বয়ংক্রিয় পরীক্ষা
ইচ্ছাকৃত বাংলাকে "অনূদিত হয়নি" বলে রিপোর্ট না করে।

একটি লোড কম্বিনেশন, একটি bar spacing বা একটি কোড-ধারা মেশিনে অনুবাদ করার ঝুঁকি
নেওয়া হয়নি — সেটি প্রসাধনী সমস্যা নয়।

## ৩. CMS পাতা

ইংরেজি সংস্করণ = একই slug + `-en` (যেমন `about` → `about-en`)। এগুলো অ্যাডমিনে
সাধারণ পাতার মতোই সম্পাদনাযোগ্য, আর `content/seed-pages-en.md` থেকে seed হয়।

`-en` পাতা না থাকলে ইংরেজি URL-এ বাংলা লেখাটিই দেখানো হয়, সঙ্গে দৃশ্যমান নোটিশ:
*"This page is not available in English yet."*

> **এখনো অনুবাদ হয়নি — ইচ্ছাকৃতভাবে:** ছয়টি আইনি পাতা
> (`privacy-policy`, `terms`, `refund-policy`, `software-eula`, `course-terms`,
> `engineering-disclaimer`)। অনূদিত আইনি ভাষা পাঠকের কাছে মালিকের নীতি হিসেবেই
> পড়া হবে, অথচ সেটি কোনো যোগ্য পেশাজীবী দেখেননি। **পেশাগত পর্যালোচনার পরে**
> ইংরেজি সংস্করণ `content/seed-pages-en.md`-এ যোগ করুন।

## ৪. প্রোডাক্টের লেখা

দাম, ভ্যারিয়েন্ট ও লাইসেন্স দুই ভাষায় একই, তাই প্রতি প্রোডাক্টে একটি রো-ই থাকে;
শুধু দুটি কলাম ভাষাভেদে আলাদা: `tagline_en` ও `description_markdown_en`।
API-তে `GET /products/{slug}?locale=en` দিলে ইংরেজি লেখা আসে, আর
`copy_translated: false` এলে পাতা নিজেই নোটিশ দেখায়।

## ৫. `/en` রুট তৈরি

`/en`-এর প্রতিটি রুট **একই পেজ কম্পোনেন্টকেই** `locale="en"` দিয়ে render করে —
দুটি আলাদা কপি রাখা হয় না।

```bash
python apps/web/scripts/generate-en-routes.py
```

`app/(public)/`-এ নতুন পাতা যোগ করলে এটি আবার চালান।

## ৬. পরীক্ষা

```bash
# প্রতিটি ইংরেজি পাতা ঘুরে দেখে বাংলা ইন্টারফেস-লেখা বাকি আছে কি না
node apps/web/tools/check-english.mjs http://localhost:3200
```

স্বয়ংক্রিয় টেস্ট: `apps/web/tests/e2e/bilingual.spec.ts` এবং
`apps/web/tests/unit/i18n-labels.test.ts`।

## ৭. SEO

- প্রতিটি পাতার নিজস্ব canonical (ইংরেজি পাতা বাংলাটির duplicate নয়)
- দুই দিকেই `hreflang` alternate (`bn-BD` ও `en`)
- sitemap-এ দুই ভাষার URL-ই আছে; `-en` CMS slug বাদ দেওয়া হয়, কারণ সেগুলো
  আলাদা URL নয়, বাংলা পাতারই `/en` সংস্করণ
